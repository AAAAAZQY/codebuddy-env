# PID 自动整定器 v2.2

输入一段响应数据，自动给出 PID 参数或调整建议。**纯 Python 标准库，零第三方依赖。**

输入可以是：**控制器输出 u**（有最好）、**目标值 r**、**实际值 y**，以及**你当前正在用的 PID 参数**。
工具会按你手头有什么，自动选一条路走：

| | 模式 A：有 u | 模式 B：无 u + 有当前 PID | 模式 C：无 u 无 PID |
|---|---|---|---|
| 输入 | `time, u, y` | `time, r, y` + PID 参数 | `time, r, y` |
| 能否辨识对象 | 能（直接辨识） | **能（由 C 反推 G）** | 不能 |
| 输出 | 5 组公式解 + 寻优解 + 鲁棒性 | **同左，完整整定方案** | 只给调整方向与幅度 |
| 精度 | 高 | 较高（看拟合 RMSE） | 中 |
| 额外要求 | u 要有明显阶跃 | 需知道当前 PID | 无 |

## 快速开始

双击 `run.bat`（或 `python pid_tuner.py`）启动图形界面：

- 点「载入示例(有u)」→ 看模式 A 效果
- 点「载入示例(无u)」→ 看模式 B 效果

命令行：

```bat
:: 模式 A
python pid_tuner.py --csv data.csv
python pid_tuner.py --csv data.csv --mode strict      :: 严禁超调
python pid_tuner.py --csv data.csv --mode aggressive  :: 追求快
python pid_tuner.py --csv data.csv --lam 0.3          :: 指定 IMC 滤波系数
python pid_tuner.py --csv data.csv --dt 0.02          :: 指定采样周期(无时间列时必需)
python pid_tuner.py --csv data.csv --plain            :: 跳过寻优/鲁棒性, 最快

:: 无 u + 已知当前 PID -> 闭环辨识, 直接算出新参数
python pid_tuner.py --csv closed.csv --current-pid "2.7,9.5,0.19"

:: 无 u 且不知道当前 PID -> 只给调整方向
python pid_tuner.py --csv closed.csv

:: 其他
python pid_tuner.py --make-sample                     :: 生成模式 A 示例
python pid_tuner.py --make-closed-sample              :: 生成模式 B 示例
python pid_tuner.py --selftest                        :: 算法自检(9 项)
python pid_tuner.py --checkenv                        :: 环境自检
python pid_tuner.py --cases                           :: 查看经验库
python pid_tuner.py --forget-cases                    :: 清空经验库
python pid_tuner.py --gui-smoketest                   :: 界面冒烟测试
```

## 输入数据格式

CSV / 制表符 / 分号 / 空格分隔均可，**首行可以是表头**，至少两列。

对**直接从串口 / 调试终端复制粘贴**的数据，做了这些容错（都是实测踩过的坑）：

| 情况 | 处理 |
|---|---|
| 全角标点（中文输入法的 `，` `：`） | 自动归一化成半角 |
| 行首前缀 `pid:1,2,3` | 自动剥掉 |
| 行首时间戳 `[12:30:45] pid:1,2,3` | 自动剥掉 |
| `data=1,2,3` / `samples 1,2,3` | 自动剥掉 |
| 末尾混入说明行 | 按出现次数最多的列宽取数据 |
| 解析失败 | 报错时打印「首行内容」帮你定位 |

> 若数据来自公司加密盘，Python 读到的是密文。工具会检测到并提示改用「粘贴数据」。

```csv
time,u,y                 <- 模式 A
0.00,0.20,0.500
0.02,0.20,0.500
0.04,0.70,0.512          <- u 发生阶跃
0.06,0.70,0.556
...
```

```csv
time,r,y                 <- 模式 B（没有 u）
0.00,0.0,0.000
0.02,0.0,0.000
0.04,1.0,0.010           <- r 发生阶跃
0.06,1.0,0.056
...
```

### 列名自动识别（列顺序可以任意）

若首行是表头，工具会**按列名识别**每列是什么：

| 角色 | 可识别的列名 |
|---|---|
| time | `time` `timestamp` `t` `时间` `时间戳` |
| u（控制器输出） | `u` `pwm` `duty` `control` `cmd` `控制量` `控制输出` `占空比` |
| y（实际值） | `y` `pv` `input` `actual` `feedback` `speed` `实际值` `实际输出` `反馈` |
| r（目标值） | `r` `sp` `sv` `setpoint` `target` `ref` `目标值` `设定值` |

因此像 `timestamp,setpoint,input,pwm` 这种列顺序完全不同的文件也能直接识别。

无表头时按列数推断：**2 列 = (u, y)；3 列 = (t, u, y)；4 列 = (t, u, y, r)**。

**2 列时有个自动判定**：如果第一列几乎恒定、第二列在明显变化，说明第一列是**目标值 r**
而不是控制量 u（开环辨识要求 u 必须有阶跃），工具会自动改判为 `(r, y)`，走经验规则整定。
典型场景就是"目标不动、输出在振"的现场记录。

### 最少需要哪几列

| 你有的列 | 能不能算 | 走哪条路 |
|---|---|---|
| `u` + `y` | ✅ **能**（这是最低要求） | 通用拟合，精度最高 |
| `u` + `y` + `r` | ✅ 更完整 | 同上，还能判断数据性质、算闭环指标 |
| `r` + `y`（无 `u`） | ✅ 能 | 需配 `--current-pid`，走闭环辨识 |
| `r` + `y`（无 `u`、无 PID） | ✅ 能 | 经验规则整定，只给调整方向 |
| 只有 `y` | ❌ 不能 | 没有任何输入信息，无法辨识 |

**关键**：`u`（控制量）和 `y`（实际值）是**不可替代**的一对——
一个是你施加的、一个是世界给你的回应，两者的对应关系就是对象的全部信息。

`r` 是锦上添花：有它工具能判断"这是开环试验还是闭环记录"、能算超调/稳态误差。
所以 `pid:r,u,y` 三路都给是最理想的，但**只给 `u,y` 也照样能算**。

### 时间列可以省略

等间隔采样时，`time` 列可以不写：

```csv
u,y
0.20,0.500
0.20,0.500
0.70,0.512
0.70,0.556
...
```

工具会用「采样序号 × 采样周期」作为时间轴，采样周期由 `--dt` 指定
（界面上是「采样周期 dt」输入框）：

```bat
python pid_tuner.py --csv data_2col.csv --dt 0.02
```

**关于单位（重要）**：

- `Kp` 是无量纲的，**不受影响**
- `T`、`τ`、`Ts`、`Ki`、`Kd` 都带时间量纲，**取决于 dt**

不给 `--dt` 时默认按 dt=1.0 处理，此时这些量的单位就是"采样周期"，
工具会在报告里给出提示。**真正要用到实机上，请务必用 `--dt` 填入真实采样周期。**

### 采集要求

**模式 A（有 u）**
1. **先稳后跳**：u 阶跃前 y 必须已经走平，否则 K 会算错（工具会告警）
2. **记满整段**：一直记到 y 完全进入稳态
3. **采样要快**：参考工具输出的「建议采样周期 Ts」
4. **别撞限幅**：阶跃幅度建议 +10%~+30%
5. **多采几次**：正反方向、2~3 个幅度各来一遍，取平均

**模式 B（只有 r、y）**
1. 目标值 r 要有**一次明显阶跃**（从某值跳到另一值）
2. 记满到响应进入稳态
3. 同一次实验**只能用同一组 PID 参数**，否则特征对不上
4. 必须知道这组参数是多少，填到 `--current-pid` 或界面输入框

## 模式 A 输出内容

1. **FOPDT 模型**：`G(s) = K·e^(-τs) / (T·s + 1)`
2. **临界参数**：临界增益 `Ku`、临界周期 `Tu`
3. **建议采样周期**：`Ts ≤ min(T/10, Tu/20, τ/3)`
4. **五组公式解**：IMC-PI、IMC-PID、Ziegler-Nichols(开环)、Cohen-Coon、Z-N 临界比例法(闭环)
5. **自动优化解**：在护栏内搜索出的评分最优参数（★推荐）
6. **统一评分**：超调、速度、稳态误差、振荡压成一个标量，越低越好
7. **响应状态诊断**：超调偏大 / 振荡未收敛 / 稳态误差 / 响应偏慢 / 良好
8. **鲁棒性检验**：K±20%、T±25%、τ±30% 扰动下批量仿真，结论分 `鲁棒/一般/敏感`
9. **数据质量告警**：阶跃前未稳态、拟合 RMSE 偏高、未到稳态、τ 小于采样周期、执行器饱和
10. **上机微调指引** + 4:1 衰减比验收参考

## 模式 B：闭环辨识（无 u + 已知当前 PID）

**原理**：闭环响应由「对象 G」和「控制器 C」共同决定。C 已知、响应又实测到了，
那么 G 就是唯一未知量——搜索 `(K, T, τ)`，让「用 C 闭环仿真出的 y」最贴合实测 y 即可：

```
搜索 (K,T,τ)  →  用已知 C 闭环仿真  →  与实测 y 比 RMSE  →  取最优
```

拿到 G 之后，就和模式 A 完全一样了：**5 组公式解 + 自动寻优 + 鲁棒性检验**，
直接给出可以写进固件的新参数。

**支持两种数据形态**（判据是「数据里有没有闭环动态」，不是「目标值有没有变过」）：

| 数据形态 | 典型来源 | 仿真方式 |
|---|---|---|
| **目标值有阶跃** | 常规的设定值阶跃实验 | 复现设定值阶跃（含微分冲击） |
| **目标值恒定但输出有动态** | **启动瞬间**的记录：目标一直是 1.0，输出从初值冲上去、衰减振荡后稳定 | 目标不动，靠**初始偏差**激发动态 |

第二类很常见——现场往往就是"上电那一刻抓一段"。只要输出变化够大（峰峰值超过均值的 3%），
就能辨识出对象，并给出完整的仿真对比曲线。

> 真正被拒的是**平坦数据**：输出只变化几个百分点，任何辨识都只是"两条直线互相比对"，
> RMSE 很小但模型毫无意义。这种情况工具会明确说明并退回经验规则。

**局限性（务必知道）**：

- 控制量中途**撞限幅**时，实测响应带着饱和特性，而仿真不知道限幅值 → 辨识会失真。
  此时拟合 RMSE 会偏大，工具会自动**退回模式 C**（只给方向），不会把错的数值给你。
- **发散**的数据辨识不出来（系统都没稳住，响应不收敛）。此时 RMSE 会远超门限，
  工具同样退回经验规则。先把增益调下来，让系统能收敛，再采数据来辨识。
- 闭环辨识存在**参数耦合**（多组 K/T/τ 能拟合同一条曲线），所以即使拟合很好，
  K 也可能有百分之几到十几的偏差。报告里的「拟合 RMSE」就是可信度指标。
- 数据必须是在**闭环下**采的，且整段用的是**同一组 PID**。

**实测精度**（用已知对象 K=2.5、T=0.8、τ=0.15 生成数据再反推）：

| | K | T | τ |
|---|---|---|---|
| 真值 | 2.5 | 0.8 | 0.15 |
| 反推 | 2.665 | 0.850 | 0.164 |
| 误差 | 6.6% | 6.2% | 9.5% |

拟合 RMSE 0.0056。

## 模式 C：经验规则整定（无 u 也无 PID）

1. **闭环响应特征**：超调量、上升时间、调节时间、稳态误差、稳态波动、**衰减比**
2. **响应状态诊断**
3. **调整动作**：抑制振荡 / 降低超调 / 消除稳态误差 / 提高响应速度 / 微调
4. **建议参数**：在当前 PID 基础上给出的新数值 + 变化倍数
5. **调整依据**：逐条说明为什么这么调

规则对照（通用工程经验法）：

| 现象 | 调整 |
|---|---|
| 衰减比接近 1 或波动大（振荡） | Kp↓、Ki↓、Kd↑ |
| 超调大 | Kp↓、Kd↑ |
| 稳态误差消不掉 | Ki↑ |
| 响应偏慢 | Kp↑ |

所有调整都会经过**参数护栏**（相对当前值限制倍数），不会一步跳到危险值。

### 目标值恒定的数据也能分析

如果整段数据里目标值 r 根本没变（典型场景：现场发现"系统一直在振"，随手抓一段），
工具会自动识别并换一套特征来分析：

- 稳态误差、**波动幅度**（峰峰值 / 目标值）、**振荡周期**、衰减比
- 据此判断是「等幅振荡」还是「持续振荡」

这种情况下**没有超调 / 上升时间 / 调节时间**的概念（没有阶跃就没有这些量），报告里不会显示。

而且这类数据**同样可能走完整的模型整定**，取决于它的动态有多丰富：

| 目标值恒定的数据 | 走哪条路 | 能得到什么 |
|---|---|---|
| 输出**持续等幅振荡**（衰减比≈1） | 频率响应反推 | 完整对象模型 + 仿真对比曲线 |
| 输出**从初值冲上去 + 衰减振荡**（启动瞬间） | 闭环辨识 | 完整对象模型 + 仿真对比曲线 |
| 输出**只在小范围抖动** | 经验规则整定 | 只给调整方向和结论 |
| 输出**发散**（越振越大） | 经验规则整定 | 先把增益降下来，收敛后再采数据 |

判据始终是「**数据里有没有闭环动态**」，而不是「目标值有没有变过」。

实测例子（目标恒为 1.0，输出在 -0.31 ~ 3.92 之间来回振）：

```
  目标值 r        : 1   (整段恒定, 无阶跃)
  实际值范围      : -0.3137 ~ 3.9167   (均值 1.74097)
  稳态误差        : -74.1 %
  波动幅度        : 423.0 %  (峰峰值 / 目标值)
  振荡周期        : 14
  响应状态        : 持续振荡 —— 稳态存在大幅波动, 先降低比例增益。
```

## 临界比例法说明

传统临界比例法要求实机把系统调到"等幅振荡"来测 `Ku`/`Tu`——对机构有风险。
本工具改为**由 FOPDT 模型解析求解**：

```
相位穿越频率 ωc:  arctan(ωc·T) + ωc·τ = π    ← 二分法解
Ku = 1/|G(j·ωc)|        Tu = 2π/ωc
```

再套用 `Kp=Ku/1.7, Ti=0.5·Tu, Td=0.125·Tu`。**不用真的把系统振荡起来**。
纯一阶对象（τ=0）不存在相位穿越，工具会自动跳过该方案。

算出的 Ku 还有独立价值：它告诉你实机做振荡实验时 Kp 该加到多少。

## 约束模式

| 模式 | 特点 | 适用 |
|---|---|---|
| `strict` 严格 | 超调惩罚权重最高 | 限位敏感、严禁过冲 |
| `balanced` 均衡 | 默认 | 大多数场景 |
| `aggressive` 激进 | 速度权重最高 | 跟踪、快速定位 |

## 调参偏好（界面上的一排按钮）

约束模式管"整体松紧"，调参偏好管"**你更在乎什么**"——点一下即按该方向重新整定：

| 偏好 | 评分里被压到最重的一项 | 附加硬指标 | 典型用法 |
|---|---|---|---|
| 综合（默认） | 各项均衡 | — | 不确定先看这个 |
| **减轻初期超调/震荡** | 超调（权重 9） | 超调 ≤ 5% | 有限位、怕冲过头的场合 |
| **减小稳态误差** | 稳态误差（权重 9） | 静差 ≤ 1% | 必须精确到位 |
| **加快响应** | 上升/调节时间（权重 6） | — | 跟踪、快速定位 |
| **稳态更平稳** | 稳态波动（权重 9） | 波动 ≤ 2% | 怕抖、怕嗡嗡响 |

两点说明：

- 偏好只改**评分权重**，整定流程、护栏、安全校验都不变
- 目标函数在"调节时间(±2%)"这类**阈值型指标**附近不光滑，局部搜索换个目标
  可能落进另一个盆地。所以选了非"综合"偏好时，工具会再做一次交叉校验：
  若综合解在该偏好下更优，就用综合解，并在报告里注明「该方向已到极限」

## 算法说明

**模式 A**：阶跃定位 → 两点法初值 + **最小二乘网格精修** → 公式整定 →
护栏内坐标下降寻优 → 闭环仿真校验（含纯滞后、抗积分饱和、发散保护）→ 鲁棒性检验

**模式 B**：目标阶跃定位 → 归一化响应 → 提取超调/时间/稳态误差/波峰衰减比 →
对照经验规则给出调整量 → 护栏裁剪

## 经验库：越用越懂你的设备

界面右下角有三个按钮：

| 按钮 | 作用 |
|---|---|
| ★ 采纳推荐参数 | 把这组参数连同"当时的工况特征"记一条 |
| ✗ 否决当前参数 | 记录「该工况下这组参数不好用」（针对上方填的当前 PID） |
| 清空经验库 | 一键遗忘全部历史 |

下次遇到**相似工况**（K、T、tau/T、数据形态、约束模式都接近）时，命中的历史参数会
自动作为**候选方案**出现在方案对比表里（名字形如 `历史案例★(相似87%)`），
同时作为自动寻优的**起点**。

要点：

- 相似度 = `1/(1+距离)`；低于 0.40 的工况不会命中——不像的工况硬套过来比不用更危险
- 历史参数**不会被特殊优待**：它一样要参与同一个模型的闭环仿真比评分，
  仿真说不行就不会被推荐，所以"学歪了"也不会把设备带偏
- 无 u 模式（经验规则路线）没有对象模型特征，无法归档，用带 u 的数据即可
- 存储在工具同目录的 `case_memory.jsonl`（纯文本，随时可删），**不联网、不上传任何数据**
- 命令行：`--cases` 查看统计、`--forget-cases` 清空、
  `--csv data.csv --remember "Kp,Ki,Kd" good` 记录一条

## 设计参考

工程化设计参考了开源项目 **llm-pid-tuner** 的思路：参数护栏、统一评分函数、
响应状态诊断、只认稳定解。整定方法与工程经验参考通用 PID 整定理论（IMC、Ziegler-Nichols、
Cohen-Coon、临界比例法、试凑法/一般调节法）。

区别：llm-pid-tuner 是在线 LLM 调参（需 API / 串口 / 第三方库）；
本工具**离线、确定性、可复现**，同一条数据每次结果完全一致。

## 注意事项

- **模式 A**：仿真基于辨识出的线性模型，实机上线请先小增益试，保留急停
- **模式 B**：没有 u 就拿不到对象模型，给的是经验规则建议，建议每次只改一个参数复测

- 鲁棒性检验只覆盖模型参数误差，**不覆盖**非线性与工况变化
- 想走模式 A，请尽量把控制器输出 u 也采集出来——这是精度差异的关键
