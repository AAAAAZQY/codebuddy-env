# MCU 软件在环仿真 —— 采集与验证指南

用**纯软件**的虚拟被控对象代替真实电机，让真实 PID 去控制它，
把数据从串口打出来喂给整定工具。**不需要电机、传感器、负载**。

整条链路：

```
application/pid_sim.c            串口(USART3,115200)          tools/pid_tuner
虚拟FOPDT对象 + PID  ──────────>  time_s,r,u,y  ──────────>   辨识 + 整定
                                                               ↓
                                                     对照 K/T/tau 验证
```

---

## 一、代码在哪

| 文件 | 作用 |
|---|---|
| `application/inc/pid_sim.h` | **所有可调参数都在这里**（对象、PID、周期、时长） |
| `application/pid_sim.c` | 实现：虚拟对象 + PID + 串口输出 |
| `application/main.c` | 已加入 `pid_sim_init()` / `pid_sim_task()`（用宏包住） |
| `application/inc/includes.h` | 已加入头文件包含 |
| `project_application/PTZ_APP.uvprojx` | 已登记 `pid_sim.c` |

**开关**：`pid_sim.h` 里的 `PID_SIM_ENABLE`
- `ON`：编译并运行仿真
- `OFF`：完全摘除，不占空间、无输出

测完建议改回 `OFF`。

## 二、默认参数（可以不改，直接测）

```c
#define PID_SIM_PERIOD_MS   20       // 采样周期 20ms
#define PID_SIM_STEP_TIME_MS 1000    // 第 1.0s 目标值阶跃
#define PID_SIM_RUN_TIME_MS 30000    // 单轮最长 30s（硬上限，一定会结束）
#define PID_SIM_EARLY_END   ON       // 达标可提前结束（配合下面两个宏）
#define PID_SIM_MIN_TIME_MS 3000     // 最短运行 3s
#define PID_SIM_STEADY_MS   400      // 误差持续小于阈值 400ms 算稳
#define PID_SIM_REPEAT      ON       // 循环跑，方便反复采集

#define PID_SIM_PLANT_K     2.5f     // 虚拟对象：增益
#define PID_SIM_PLANT_T     0.8f     // 虚拟对象：时间常数(s)
#define PID_SIM_PLANT_TAU   0.15f    // 虚拟对象：纯滞后(s)

#define PID_SIM_KP          1.5f     // 初始 PID（故意偏激进，留出改进空间）
#define PID_SIM_KI          3.0f
#define PID_SIM_KD          0.05f
```

> **记住这三个数：K=2.5、T=0.8、τ=0.15**
> 待会儿整定工具反推出来的值应该接近它们——这就是验证通过的标志。

## 三、输出串口的选择

在 `pid_sim.h` 里用宏切换：

```c
#define PID_SIM_OUT_UART   1        // 0=调试口(USART3)   1=RS485口(UART1)
#define PID_SIM_RS485_BAUD 115200   // 选485时临时提速; 填0=保持工程默认9600
```

### 方案 A：调试口（最省事）

- **USART3**（TX=PB10，RX=PB11），**115200 8N1**
- 用 USB 转 TTL 接这两根线（TX↔RX 交叉）
- 发送走 FIFO 中断，**不阻塞主循环**
- 设 `PID_SIM_OUT_UART = 0`

### 方案 B：RS485 口

- **UART1**（TX=PA9，RX=PA10），方向控制脚 **PA8**（工程既有的 `RS485_CTRL`）
- 用 USB-485 转换器接到 **A/B** 两根差分线上（A 接 A，B 接 B）
- 发送走**轮询、会阻塞**，而且 485 是半双工，所以：
  - **必须把波特率提到 115200**（`PID_SIM_RS485_BAUD = 115200`）
  - 电脑端 USB-485 **也要设成 115200**
- 代码用工程既有的 `board_uart_cmd_send()`，它会自动切换收发方向

> **为什么 485 一定要提速？**
>
> 485 在工程里默认是 **9600**。一行数据约 30 字节，9600 下发完要 **31ms**；
> 而本模块每 20ms 就发一行 → 主循环会被发送占满。
> 115200 下同样一行只要 **2.6ms**（占 13%），可以接受。
>
> 如果必须保持 9600，那就得把 `PID_SIM_PERIOD_MS` 调到 **>= 40**。
> 配置不合规时**编译会直接报错**提醒（特意加的编译期检查）。

### 注意事项（485 特有）

485 平时还用于和 IPC 通信（PELCOD 协议）。测试期间：

- 我们的 ASCII 数据会混进 PELCOD 帧流里，IPC 一般会把不认识的帧丢掉
- 反过来 PELCOD 帧也可能插进我们的数据行，导致**个别行损坏**
- 整定工具会**自动跳过解析不了的行**，丢几行不影响结果
- 最干净的做法：测试时把 485 总线从 IPC 上摘下来，或单独接一路 USB-485

### 输出协议：FireWater / VOFA+ 兼容

输出是**纯 CSV 字符串流**，格式就是串口波形工具常用的 FireWater 协议：

```
<any>:ch0,ch1,ch2,ch3<换行>
```

实际长这样（默认配置）：

```
# ===== PID software-in-loop test =====
# uart   : RS485 (UART1)
# plant  : K=2.5000  T=0.8000  tau=0.1500
# pid    : Kp=1.5000  Ki=3.0000  Kd=0.0500
# period : 20 ms    run: 8000 ms    step at: 1000 ms
# dt_s   : 0.0200
pid:r,u,y
pid:0.0000,0.0000,0.0000
pid:0.0000,0.0000,0.0000
...
pid:1.0000,4.0600,0.0000
...
```

要点：

- **通道顺序**：`r, u, y`，共 **3 路**（目标值、控制量、实际值）
- **换行**：用 `\r\n`（协议也允许 `\n` / `\n\r`）
- **`#` 开头的行是注释**，两边都会忽略
- **前缀 `pid:` 可去掉**：把 `PID_SIM_HAS_PREFIX` 设成 `0` 就是纯 CSV
- 前缀名**不要用 `image`**（那个留给图片数据）

### 为什么默认不带"时间"这一路

时间列对整定工具很有用，但**会毁掉 VOFA+ 的波形**：

> VOFA+ 没有"时间轴"的概念，它把**每一路通道都当曲线画**。
> 如果时间也作为一路发出去，它就会被画成一条笔直上升的斜线，
> 而每轮跑完重启时又跳回 0 —— 看起来就是**锯齿波**。

所以默认 **不发时间列**，而用注释行 `# dt_s : 0.0200` 把采样周期告诉上位机。

| 上位机 | 怎么用 |
|---|---|
| **VOFA+** | 选 **FireWater** 协议 → 干净的 3 条曲线 |
| **整定工具** | 读 `# dt_s` 自己补时间轴 → 自动剥离前缀、识别表头 |

同一份数据，两边都能用，**不需要你做任何手工处理**。

> 想恢复带时间列的 4 通道版本（整定工具更直观，但 VOFA+ 会出现锯齿）：
> 把 `pid_sim.h` 里的 `PID_SIM_SEND_TIME` 设成 `1` 即可。

> **带宽提示**：FireWater 是文本协议，解析比二进制费资源。
> 本场景 3 通道 @ 50Hz，一行约 30 字节 → 1500 字节/秒，很轻。
> 若把采样周期调到 5ms（200Hz），就是 6000 字节/秒，
> 在 115200（约 11520 字节/秒）下占用过半，需要留意。

## 四、采集数据

1. 编译烧录（Keil 打开 `PTZ_APP.uvprojx`，Build → Download）
2. 打开串口助手（SSCOM / XCOM / 串口调试助手都行）
3. 选择对应 COM 口，**115200 8N1**
4. **关闭"时间戳"和"按行分帧"之类的前缀功能**（否则数据行前面会多出字符，整定工具解析不了）
5. 点"接收"或"开始"，等一轮跑完（8 秒后会打印 `# ===== round end =====`）
6. 保存接收内容为 `.csv`

你会看到这样的输出：

```
# ===== PID software-in-loop test =====
# plant  : K=2.5000  T=0.8000  tau=0.1500
# pid    : Kp=1.5000  Ki=3.0000  Kd=0.0500
# period : 20 ms    run: 8000 ms    step at: 1000 ms
time_s,r,u,y
0.0000,0.0000,0.0000,0.0000
0.0200,0.0000,0.0000,0.0000
...
1.0000,1.0000,4.0600,0.0000
1.0200,1.0000,1.6200,0.0000
...
# ===== round end =====
```

**`#` 开头的行是注释**，整定工具会自动忽略，不用手工删。

## 五、用整定工具分析

```bat
cd tools\pid_tuner

:: 完整数据（推荐）：直接把 r/u/y 全喂进去，并说明当前 PID
python pid_tuner.py --csv 你保存的文件.csv --current-pid "1.5,3.0,0.05"
```

工具会自动：
1. 识别出这是**闭环运行记录**（因为 u 在持续调节，不是恒定阶跃）
2. 用实测的 u 驱动 FOPDT 模型，拟合出对象参数
3. 给出 5 组公式解 + 自动寻优解 + 鲁棒性检验

### 期望结果（离线验证过的）

```
反推对象: K=2.5000(0.0%)  T=0.7981(0.2%)  tau=0.1345(10.3%)
拟合 RMSE: 0.00058
推荐参数: Kp=0.6769  Ki=0.8481  Kd=0.0044   (当前 1.50 / 3.00 / 0.050)
```

**看到 K≈2.5、T≈0.8 就说明整条链路是通的。**

### 还想验证别的场景

```bat
:: 没有 u 的情况（把 u 列删掉再喂）：走闭环辨识，由已知 PID 反推对象
python pid_tuner.py --csv 只有ry的文件.csv --current-pid "1.5,3.0,0.05"

:: 连 PID 都不告诉它：工具会自己从数据里反推
python pid_tuner.py --csv 你保存的文件.csv
```

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 串口完全没输出 | 确认 `PID_SIM_ENABLE` 是 `ON`；确认烧录成功；确认接线 |
| 485 上完全没有输出 | 没用带方向控制的发送函数（本模块已用 `board_uart_cmd_send`）；或 A/B 线接反 |
| 输出乱码 | 波特率不一致：选 485 时 `PID_SIM_RS485_BAUD` 与电脑端 USB-485 必须相同 |
| 编译报错 "RS485 保持 9600 时..." | 按提示把 `PID_SIM_RS485_BAUD` 设为 115200，或把采样周期调到 >= 40ms |
| 整定工具报"有效数据点太少" | 串口助手开了时间戳前缀，把每行都搞成非数字了 → 关掉重采 |
| 整定工具说"时间轴看起来是采样序号" | 时间列没被识别（表头被改过）→ 保持 `time_s` 表头 |
| 反推出的 K 差很多 | 控制量撞了限幅（默认 ±10，不会撞）；或数据被截断 |
| τ 误差偏大（10% 左右） | 正常现象。τ 只有 3 个采样周期（0.15/0.02），分辨率有限；想更准就把 `PID_SIM_PERIOD_MS` 调到 10 |
| 板子反复复位 | 仿真任务被阻塞了。本实现是非阻塞的，一般不会；检查是否自行加了 `timer_delay` 长延时 |

## 八、想自己改参数试

改 `pid_sim.h` 里的宏即可，例如：

```c
#define PID_SIM_KP   2.7f      // 换个激进的参数，看工具能不能把它拉回来
#define PID_SIM_KI   9.5f
#define PID_SIM_KD   0.19f
#define PID_SIM_PLANT_T  1.5f  // 换个更慢的对象
```

改完重新编译，重复第四、五步。

> **注意**：改完宏之后，`mc_sim_verify.py` 顶部的常量也要同步改，
> 否则离线验证和你板子上的行为就不一致了。

## 九、单位约定（重要）

- 串口输出的时间轴统一用**秒**（`time_s`）
- 这与 PID 参数 Kp/Ki/Kd 的时基**保持一致**
- 整定工具输出的 Ki/Kd 也是秒制，可以直接填回 `pid_sim.h`

如果改成毫秒输出，整定出来的 Ki/Kd 会差 1000 倍。
